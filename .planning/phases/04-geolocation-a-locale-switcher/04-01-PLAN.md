<task type="auto">
  <name>Task 2: Create middleware for geolocation redirect</name>
  <files>src/middleware.ts</files>
  <action>
Create Next.js middleware with this detection priority:

1. **Skip if path already has locale prefix** - Check if pathname starts with any locale (us, nl, dk, au, uk, ie). If yes, return NextResponse.next() (pass through, no redirect).

2. **Skip API routes, static files, Next.js internals** - Matcher config excludes these.

3. **Check NEXT_LOCALE cookie** - If exists and valid, redirect to that locale with 302.

4. **Detect via Vercel geolocation** - Read `x-vercel-ip-country` header (or use `geolocation()` helper from @vercel/functions if available). Map country to locale via geo-utils.

5. **Fallback to default locale** - If no match, redirect to 'us'.

6. **Set NEXT_LOCALE cookie on geolocation redirect** - When redirecting based on geolocation (not cookie), set the cookie for future visits. Use 1-year maxAge.

GDPR NOTE: The NEXT_LOCALE cookie is classified as "strictly necessary" for the site's core functionality (multi-locale navigation). Under GDPR Article 5(3) and ePrivacy Directive, strictly necessary cookies do NOT require consent. This cookie:
- Only stores a 2-letter locale code (us, nl, dk, etc.)
- Is essential for the site to function correctly (remember user's region)
- Does not track users or share data with third parties
- Is equivalent to a shopping cart or session cookie

Therefore, the middleware may set this cookie before the consent banner shows. The consent banner informs users about cookies but consent is not legally required for this specific cookie.

Implementation details:
- Use NextResponse.redirect(url, 302) for SEO-compliant temporary redirects
- Matcher config: `['/((?!api|_next|_vercel|.*\\..*).*)',]` to exclude static files
- Development fallback: When x-vercel-ip-country header is missing (local dev), fall back to 'us'
- Do NOT use @vercel/functions package - read headers directly to avoid dependency issues
- Cookie settings: `{ maxAge: 31536000, path: '/', sameSite: 'lax' }`

Handle edge cases:
- Empty pathname should redirect to /{locale}
- Pathname "/" should redirect to /{locale}
- Pathname "/services" should redirect to /{locale}/services

**MIDDLEWARE MATCHER COMPATIBILITY (CRITICAL):**
The middleware matcher MUST NOT interfere with existing [locale] routes. Verify:
- Requests to /us/, /nl/, /dk/, /au/, /uk/, /ie/ pass through WITHOUT redirect
- Only requests WITHOUT a locale prefix get redirected
- Test by checking that /us/services, /nl/contact, etc. render normally (no redirect loop)

The skip logic in step 1 ("Skip if path already has locale prefix") is what prevents interference. Ensure this check happens BEFORE any redirect logic.
